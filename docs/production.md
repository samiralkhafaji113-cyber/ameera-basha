# الإنتاج – Production (Supabase + Vercel)

> الحالة بصراحة: كل ما يمكن تنفيذه **محلياً** نُفِّذ واختُبر. ما يحتاج حسابك (مشروع Supabase، مشروع Vercel، الدومين) **لم يُنفَّذ** وعلامته `NOT VERIFIED` أدناه، وخطواته في [deployment.md](deployment.md).

## 1. البنية الحالية (Current Architecture)

| العنصر | ما هو موجود فعلاً |
|---|---|
| **Frontend** | Next.js **16.3.5** (App Router, Turbopack)، React 19.2، TypeScript، Tailwind 4، RTL. الموقع العام في `src/app/(site)`، اللوحة في `src/app/admin` |
| **Backend** | لا خادم منفصل: Server Components + **Server Actions** (`src/app/admin/actions/*`, `src/app/actions/reservation.ts`) + Route Handlers: `POST /api/admin/media` (رفع الصور) و`GET /api/health` |
| **Database** | Supabase Postgres 17. 6 migrations في `supabase/migrations` (المخطط، المنطق/Triggers/RPC، RLS، Storage، تقوية الإنتاج، قراءة سجل الـslug) |
| **Storage** | Bucket واحد `store-media` (قراءة عامة، كتابة للموظفين، حذف لـadmin/manager، WebP فقط، ≤ 2MiB). صور الموقع الثابتة (الشعار، صور المحل، OG) تبقى في `public/` (تُخدَّم من CDN الاستضافة ومُنسَّخة مع الكود) |
| **Authentication** | Supabase Auth (بريد + كلمة مرور، التسجيل العام مغلق). الأدوار في `public.profiles` |
| **Admin** | `/admin/*` محمية بأربع طبقات: `proxy.ts` ← حارس الصفحة ← حارس الـAction/Route ← RLS. غير المسجَّل → `/admin/login`، المسجَّل بلا صلاحية → `/admin/access-denied` |
| **Reservations** | RPC `create_reservation` (SECURITY DEFINER): تحقق كامل في الخادم، رقم `AB-YYYYMMDD-NNNN`، Snapshot للمنتج والمقاس والسعر (المؤكَّد فقط)، حد 5/ساعة لكل هاتف. واتساب رابط جاهز فقط ولا يُرسَل تلقائياً |
| **Images** | رفع عبر Route Handler: فحص magic bytes + حجم + أبعاد ← إعادة ترميز WebP بلا EXIF ← Storage. المتصفح يصغّر الصورة أولاً (حد جسم الطلب على Vercel ≈ 4.5MB) |
| **Deployment** | جاهز لـVercel: `vercel.json` (المنطقة fra1)، `engines.node = 24.x`، حارس بيئة الإنتاج في `next.config.ts` |

مطابقة أعمدة الطلب مع المخطط الحالي (لا ازدواجية): `age_range` = `age_min`+`age_max`؛ `categories.image` = `image_path`+`image_url`؛ زيادات موثّقة: `deleted_at` (حذف ناعم)، `search_text`، `size_label`، `numeric_sizes`، `price_snapshot`/`currency_snapshot`.

## 2. متغيرات البيئة (فُحص الكود فعلياً)

| المتغير | أين يُقرأ | Production | Preview | Development |
|---|---|---|---|---|
| `NEXT_PUBLIC_SITE_URL` | `src/lib/site.ts` (sitemap, canonical, OG, JSON-LD) | `https://دومينك` | اتركه فارغاً (يستعمل عنوان المعاينة تلقائياً) | فارغ |
| `NEXT_PUBLIC_SUPABASE_URL` | `src/lib/supabase/*`, `next.config.ts` | مشروع الإنتاج | مشروع تجريبي **أو اتركه فارغاً** (انظر 5) | `http://127.0.0.1:54321` |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | `src/lib/supabase/*`, `src/proxy.ts` | مفتاح anon للإنتاج | مفتاح المشروع التجريبي | محلي |
| `SUPABASE_SERVICE_ROLE_KEY` | **سكربتات المشغّل فقط** (`scripts/*.mts`) | ❌ لا يوضع في Vercel | ❌ | ملف `.env.local` محلي |
| `NEXT_BUILD_CPUS` | `next.config.ts` (اختياري) | — | — | جهاز قليل الذاكرة |

- `.env.example` بلا أي قيمة سرية أو حساب. الملفات الحقيقية `.env.local` و`.env.production.local` خارج Git (`.gitignore`).
- بناء **Production** على Vercel يفشل مبكراً (وبأسماء المتغيرات فقط، بلا قيم) إن كان `NEXT_PUBLIC_SITE_URL` غير https/placeholder/localhost أو ناقصاً أحد متغيرات Supabase. الفحص نفسه محلياً: `npm run prod:check-env`.
- مفتاح `anon` ليس سرّاً (RLS تحميه)؛ الأسرار الحقيقية: `service_role` وكلمة مرور قاعدة البيانات وحساب الأدمن.

## 3. ترحيل البيانات (Local → Production)

المصدر: `src/data/catalog.generated.json` + `public/products/**` (وهو نفسه ما استُورد في قاعدة البيانات المحلية). **القياسات المحلية قبل الترحيل** (`npm run db:audit` → `supabase/local-audit.json`):

| | القيمة |
|---|---|
| المنتجات | 72 (منشور 72 · مخفي 0 · مؤرشف 0 · مسودة 0 · محذوف 0) |
| الصور | 282 (كل منتج له صورة رئيسية واحدة) |
| بسعر / بلا سعر | 22 / 50 (كلها غير مؤكدة العملة) |
| حسب القسم | نسائية 22 · أطفال 21 · مدرسية 3 · قرطاسية 3 · إكسسوارات 15 · مفروشات 8 |
| الحجوزات | 0 (بعد تنظيف بيانات الاختبار) |

- **`npm run prod:seed`**: يدرج ما ينقص فقط، بمفتاح `(source, source_post_id)`؛ لا يكرّر ولا يكتب فوق تعديلات الأدمن. يحفظ الاسم، الـslug، الوصف، القسم، السعر، المقاسات، العمر، التوفر، featured، المصدر، الرابط، معرّف المنشور وتاريخه. **العملة لا تُفترض**: `currency=NULL, price_verified=false` (الموقع يعرض «السعر عند الاستفسار» حتى يؤكدها الأدمن).
- الرفع إلى مشروع بعيد يتطلب `--allow-remote` (مضاف تلقائياً في `prod:*`)، ويُطبع اسم المشروع الهدف قبل أي تغيير. إعادة التشغيل على مشروع فيه بيانات تحتاج `--yes` (لأن منتجاً حذفه الأدمن نهائياً سيعود).
- **`npm run prod:verify`** يقارن المصدر المحلي بالهدف: المنتجات والصور، المفقود، المكرَّر، الصور الرئيسية الناقصة، **وفحص HTTP لكل رابط صورة** (يجب 200 + `image/webp`). يخرج بالرمز 1 عند أي نقص ولا يجوز إعلان النجاح حينها. نتيجته على قاعدة **محلية** الآن: 72/72 منتجاً، 282/282 صورة، 0 مفقود، 0 مكرر، 0 روابط معطوبة (PASS). على الإنتاج: `NOT VERIFIED` حتى تشغّله.
- بيئتك المحلية لا تُمَس: كل السكربتات تقرأ ملف env تختاره أنت.

## 4. Storage

* `store-media` (الاسم بدل `product-images` المقترح كي لا نضاعف الـbucket: يخدم صور المنتجات وأغلفة الأقسام). لا bucket `site-assets`: صور الموقع الثابتة تعيش في `public/` ومُنسَّخة مع الكود، وهذا أسرع وأبسط.
* سياسات: قراءة عامة للروابط (لا سرد للملفات)، **إدراج/تعديل** للموظفين، **حذف** لـadmin/manager فقط، ولا كتابة لأي مجهول. الـbucket نفسه يرفض غير WebP وما فوق 2MiB حتى لو تسرّب توكن موظف.
* التحقق عند الرفع (الخادم): الامتداد/النوع المُعلَن يُتجاهل، **magic bytes**، الحجم ≤ 8MB، الأبعاد 200–8000px، ثم إعادة ترميز.

| البيئة | قاعدة البيانات | ملاحظات |
|---|---|---|
| Development | Supabase محلي (Docker) | `npm run db:start` |
| Preview | **الأفضل**: مشروع Supabase تجريبي (staging). **الخيار الآمن الافتراضي**: لا تضع متغيرات Supabase في Preview ← يعمل الموقع على الكتالوج الثابت وتُعطَّل اللوحة والحجز، فلا يمكن أن تلمس المعاينة بيانات الإنتاج | لا تشارك مفاتيح الإنتاج مع Preview |

## 6. النسخ الاحتياطي (Backup)

1. **قاعدة البيانات**: تحقق من خطتك في Supabase → Database → Backups. نسخ يومية تلقائية للخطط المدفوعة، وPITR إضافة اختيارية؛ خطة Free **لا تشمل** نسخاً مُدارة، لذلك شغّل `npm run prod:backup` بانتظام.
2. **نسخة قابلة للنقل من جهازك**: `npm run prod:backup` ← `backups/<تاريخ>/` (JSON لكل الجداول + كل ملفات `store-media` بمساراتها). المجلد **خارج Git** لأنه يحوي بيانات عملاء؛ احفظه في مكان مشفّر.
3. **قبل أي تغيير بنيوي على الإنتاج**: `npm run prod:backup` + (اختياري) `npx supabase@2.117.0 db dump --linked -f backups/full.sql`.
4. **الاستعادة**: الصور: `npx tsx --env-file=.env.production.local scripts/restore-storage.mts backups/<تاريخ> --allow-remote` (تعيد نفس الروابط، لا تحذف شيئاً). الجداول: من نسخ Supabase/PITR أو من `full.sql`؛ ملفات JSON مرجع قابل للقراءة والاستيراد الانتقائي.
5. اختُبر محلياً: النسخ الاحتياطي (290 ملفاً، 9.5MB) واستعادة الصور ثم `db:verify` = PASS.

## 7. خطة التراجع (Rollback)

| ما | كيف |
|---|---|
| التطبيق | Vercel → Deployments → النسخة السابقة → **Promote to Production** (فوري، لا يمس البيانات) |
| قاعدة البيانات | الـmigrations للأمام فقط وغير هدّامة. للتراجع عن آخر تغيير: `supabase/rollback/*.down.sql` (لا تُنفَّذ تلقائياً). لأي مشكلة أكبر: الاستعادة من نسخة/PITR بعد أخذ نسخة من الحالة الحالية |
| الصور | `restore-storage.mts` من آخر نسخة، أو `prod:seed` لإعادة صور الكتالوج الأصلي |
| البيانات المستوردة | `prod:seed` لا يحذف؛ وأي منتج حذفه أدمن نهائياً يعود بإعادة التشغيل فقط عند تمرير `--yes` |

قاعدة عامة: **لا عملية هدّامة على الإنتاج أثناء الاختبار**؛ اختبارات E2E تستعمل منتجاً وحجزاً بوسم `TEST` وتحذف المنتج بنفسها، ويُنظَّف الحجز بـ`npm run prod:cleanup-test-data`.

## 8. الأخطاء والمراقبة

* `src/instrumentation.ts` يسجّل كل خطأ خادم غير معالَج كسطر JSON واحد (المسار + الطريقة + digest + رسالة **مُنقَّحة**) في Vercel Logs. يحذف `redact()` الرموز (JWT/مفاتيح/Bearer)، البريد، أرقام الهاتف، وأزواج password/token، ولا يسجّل ترويسات ولا كوكيز ولا أجسام ولا query strings (اختُبر بوحدات).
* `GET /api/health` (عام، بلا تفاصيل): `ok` عند وصول قاعدة البيانات كزائر. ضعه في أي مراقب Uptime.
* لا أدوات تحليلات تستقبل بيانات العملاء. يمكن لاحقاً وصل متتبّع أخطاء من نفس الملف.

## 9. الأداء

* الموقع العام: صفحات ISR مع كاش موسوم `catalog` (تحديث فوري عند تعديل الأدمن + 5 دقائق كحد أقصى)؛ 14–27ms محلياً. الاستعلام واحد للقائمة (صور مضمّنة — بلا N+1).
* اللوحة: ترقيم 20 منتجاً/حجزاً لكل صفحة، 24 صورة في الوسائط؛ لا تُحمَّل كل المنتجات/الحجوزات دفعة واحدة. ~250ms محلياً.
* الحد المعروف: صفحة `/products` تحمّل كل المنتجات المنشورة (حتى 1000) وتفلترها في المتصفح. مناسب لعشرات–مئات المنتجات؛ عند تجاوز ذلك يلزم ترقيم/بحث من الخادم.
* حجم JS للصفحات العامة ≈ 193–200KB (gzip)، ولم يتغير عملياً مقارنةً بما قبل الخلفية.

## 10. الـ SEO

Metadata والـOG للمنتج من قاعدة البيانات (صورة الغلاف من Storage). الـsitemap: الرئيسية + المنتجات + **المنشورة فقط** (المخفي/المؤرشف/المحذوف/المسودة لا يظهر). JSON-LD: الصور تُبنى صحيحة لروابط Storage المطلقة (كان سيُنتج رابطاً معطوباً؛ أُصلح واختُبر). لا `offers` لأن العملة غير مؤكدة. **TikTok** يبقى «Probable» وخارج `sameAs`. تغيير `slug` يحفظ القديم ويعيد توجيهه (308) إلى الجديد للمنتجات المنشورة فقط.
